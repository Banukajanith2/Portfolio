# Project rules

Standing instructions for this repo. These are decisions already made - follow
them without re-asking.

## Writing style

- **Never use em dashes (`-`) or en dashes (`-`). Use a regular hyphen `-`.**
  This applies everywhere: UI copy, `data/portfolio.ts`, code comments, commit
  messages, README, and any file you create. If you catch one, replace it.
- Prefer plain hyphens for ranges too: `10-15 variables`, `2022-2024`.

## Design system

The theme is **"Acid Lime on Ink"**: a single lime accent on near-black, with
everything else neutral. Do not introduce a second accent hue - use weight,
size and spacing for hierarchy instead.

- Colour tokens live in [app/globals.css](app/globals.css) as bare `R G B`
  channels so Tailwind's `<alpha-value>` opacity utilities compile. Reading a
  token in raw CSS needs `rgb(var(--token))`.
- `--accent` is the lime fill, `--accent-contrast` is text drawn on top of it,
  and `--accent-fg` is accent-coloured *text* - it darkens to olive in light
  mode, because lime text is illegible on paper.
- `.display`, `.mono-label`, `.section-container` and `.card` live in
  `@layer components`, **not** `@layer utilities`. Tailwind emits user
  utilities after its generated ones, so a `.mono-label` in the utilities layer
  silently overrides any `text-*` colour applied alongside it. Keep them there.

## Motion

- Everything animated must honour `prefers-reduced-motion`, via
  `useReducedMotion()` in JS or the global media query in `globals.css`.
- Reusable primitives are in [components/ui/](components/ui/): `Reveal`,
  `KineticText`, `SpotlightCard`, `Magnetic`, `CountUp`, `VelocityMarquee`,
  and the `Ambience` layers. Reach for these before writing a new one.
- `SpotlightCard` takes layout classes on `contentClassName`, not `className` -
  the light layers force the children one level down, so `grid`/`flex` on the
  outer shell would lay out a single wrapper instead of the children.
- Framer Motion writes `transform` inline for `x`/`y`, which overwrites
  Tailwind translate utilities. Put centring offsets on an inner element.

## 3D / WebGL layer

- **`@react-three/fiber` is pinned to v8.** v9 requires React >= 19 and this
  project is on React 18. Do not run `npm update` on it without upgrading React
  first - npm will happily install v9 and the app will fail at runtime.
- The canvas is mounted through [components/three/HeroCanvas.tsx](components/three/HeroCanvas.tsx),
  which exists because `ssr: false` is only legal inside a Client Component on
  the App Router. Calling `dynamic(..., { ssr: false })` from `app/page.tsx`
  is a build error.
- [lib/capability.ts](lib/capability.ts) decides whether to draw at all.
  `prefers-reduced-motion`, no WebGL context, <= 2 cores or <= 2GB RAM all
  return tier `off` and the canvas never mounts - the CSS aurora is the
  fallback and is a complete background on its own.
- Keep three.js out of the initial bundle. First Load JS should stay around
  187 kB; if it jumps by ~150 kB, something imported `three` eagerly.
- The scene must stay theme-aware. Additive blending only builds toward white,
  so it disappears on the light theme - light mode switches to normal blending
  with the darker accent, the same problem `--accent-fg` solves for text.
- Particles are one `THREE.Points` with a custom shader (one draw call, buffers
  uploaded once). Never animate particle positions from JavaScript.

## Smooth scroll

- Lenis, not GSAP ScrollSmoother. Lenis animates the **native** scroll position,
  so Framer Motion's `useScroll`/`useVelocity`, `position: sticky` on the
  project stack, and `IntersectionObserver` in `useActiveSection` all keep
  working. A transform-based smoother breaks every one of those.
- Do not pass an offset to `lenis.scrollTo`: `scroll-padding-top` in
  `globals.css` already reserves the navbar's space, and passing both lands
  anchored sections twice as far down the page.

## Content honesty

Do not ship placeholder art presented as real work. Project covers in
`public/images/` are generated by
[scripts/gen-placeholders.mjs](scripts/gen-placeholders.mjs) as abstract plots
of what each project does, deliberately not mock screenshots.

## Verifying

Before calling UI work done, run the app and look at it - screenshot the page
across both themes and at mobile width. Several layout bugs in this repo
(collapsed bento grids, swallowed accent colours, clipped headings) type-checked
and linted clean but were obvious on sight.

```
npx tsc --noEmit && npm run lint && npm run build
```
